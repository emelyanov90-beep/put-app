# Проверка фронтенда «Путь» перед подключением backend

**Вердикт: NOT READY FOR RELEASE.** Проверка и исправления выполнены в текущем репозитории; полноценный серверный end-to-end и Definition of Done из приложенного промпта не достигнуты. По прямому запросу владельца БД/backend/сервер оставлены следующему этапу. Кроме этой плановой границы найдены незавершённые frontend-разделы — их нельзя считать внешними блокерами.

Основание: полный [ТЗ](TZ_Put_Flutter_PocketBase.md), [PRODUCT_RULES](PRODUCT_RULES.md), инструкции проекта и актуальная [Figma](https://www.figma.com/design/1xjkDXml6iucrxKL7e5YSk/BlaBlaCar?node-id=43-33059). Использована ссылка из сообщения пользователя; другая ссылка во вложенном промпте не принята за актуальный макет. Дата: 06.09.2026.

## Фактически выполнено

Приложение установлено и запущено на отдельном Android-эмуляторе `emulator-5556`; существующий пользовательский эмулятор и его данные не очищались. Native integration test проходит реальные Flutter-экраны, вводит текст, нажимает кнопки и сохраняет PNG. Auth, каталог, гараж, публикация и чат в этом тесте используют существующие preview-данные. Это проверка UI, не работа двух пользователей с сервером.

| Область | Проверено запуском на Android | Граница доказательства |
|---|---|---|
| Первый вход | Welcome, onboarding, телефон, согласие с документом, неверный OTP и `111111` | OTP пока локальный, серверная сессия не создаётся |

| Пассажир | Список авто, пустой автобусный список, полная/доступная поездка, детали, лист бронирования | Поиск на backend и актуальность мест не подтверждены |
| Бронирование | Нажатие отправки при отсутствующем API → понятная ошибка, без фиктивной оплаты | Standard/instant переходы дополнительно проверены unit/widget tests с подменой repository |
| Заказы | Список, детали, подтверждение отмены, отказ от отмены, ошибка недоступного сервиса отмены | Само серверное списание/возврат/освобождение места не выполнялось |

В PRODUCT_RULES есть более раннее уточнение о показе после подтверждения; конфликт явно сохранён здесь, а не молча объявлен решённым на уровне серверной модели. На backend нужны отдельные публичный и приватный DTO, защищённый СТС и проверка участников.

## Сверка с Figma

Получена структура файла Figma; изучены группы onboarding/auth/profile, пассажирский поиск/бронирование/заказы, водительский мастер/отклики, автомобили и системные состояния. Из API получены design context и изображения выборочных эталонов, включая `43:42050` (список поездок) и `43:51927` (профиль пассажира). Проверены собственные native-снимки списка, деталей, профиля, гаража и мастера. Полная сверка каждого Figma-frame и всех связей прототипа не выполнена.

Подтверждённые расхождения/ограничения:

- Тема называет Gilroy, но шрифтовых файлов и `fonts:` в pubspec нет: Android использует fallback. Типографику нельзя считать соответствующей макету.
- Часть аватаров/иконок — Material placeholders; фотографии и состояния требуют полного сопоставления с экспортами Figma. В карточках часть данных демонстрационная.
- Форма запроса оплаты пока стандартный диалог; требуется макет с серверной комиссией и итогами.
- При отсутствии отзывов добавлен перенос по требованиям ТЗ; это осознанно важнее воспроизведения фиктивного 4.5 из демонстрационного макета.
- Скриншоты не являются pixel-diff/golden проверкой; системные панели в native integration-серии не входят в эту сверку.

| P1 | Не реализовано восстановление после сетевого timeout/истечения auth; списки используют статичные снимки | Reload/retry/refresh и единое repository-состояние |
| P2 | Неполная Figma-сверка, нет Gilroy и части финальных ассетов | Полный визуальный проход после подключения ресурсов |

`PendingFlowScreen` теперь даёт понятный возврат вместо технической заглушки, но перечисленные функции от этого не стали реализованными. Статичные майские даты, условные расстояния, одобренные демонстрационные авто и тестовые заказы не являются пользовательскими данными.

Бизнес-правила на **работающем backend не проверены**: миграции отсутствуют, `pb_hooks/main.pb.js` содержит каркас, seed не реализован. Нет основания утверждать безопасность чужих коллекций, атомарность, доступность вне РФ, восстановление переписки или успешный mock-refund. Это запланированный объём разработки, не только внешняя недоступность сервера.

## Автоматические проверки и артефакты

Результаты сборок и финальной проверки экранов приведены в [журнале QA](qa/README.md). Тесты с подменой API прямо отделены от native UI и от отсутствующего server E2E.

Код изменён преимущественно в `lib/app/{router,bootstrap}.dart`, auth/profile controllers, rating/domain-моделях, `features/trips/{application,data,presentation}`, выборе изображений и формах vehicles. Добавлены `integration_test/frontend_audit_test.dart`, `test_driver/frontend_audit_driver.dart`, тесты bootstrap, booking controller и SDK-контракта; обновлены затронутые widget tests. `pubspec` добавляет SDK `integration_test`.

Исходное рабочее дерево содержало большой объём незакоммиченных экранов и документов пользователя. Они сохранены; общий `git diff` не равен объёму данного аудита. Backend не развёрнут, production-данные не менялись, commit не создавался.

Дальнейшие работы: [план backend и сервера](BACKEND_IMPLEMENTATION_PLAN.md). До выполнения перечисленных обязательных сценариев и закрытия frontend-пробелов вердикт остаётся **NOT READY FOR RELEASE**.

Дополнительная проверка 320×568 dp выявила и устранила два переполнения onboarding: первый экран теперь прокручивается при недостатке высоты, на втором учтена фиксированная высота индикатора. Тесты исходных Figma-координат на 375×812 продолжают проходить.

На форме телефона добавлена прокрутка при открытой клавиатуре на 320 dp; regression test проверяет доступность отправки номера без RenderFlex overflow.

На финальном экране водительского preview явно указано, что поездка тестовая и другим пользователям пока не видна. Кнопка отмены больше не обещает возврат денег; строкам диалога на узком экране выделена полная ширина.

Защита от поздних async-ответов также применена к аватару профиля и черновика: результат старого выбора игнорируется после reset/смены сессии. Добавлены три regression tests, включая invalidate с повторным созданием состояния.
